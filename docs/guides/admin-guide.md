# 관리자 가이드

> **대상**: 도서관 운영 관리자.
> **플랫폼**: 웹 대시보드 (`/admin/*` 경로).
> **버전**: v0.6.0 기준.

관리자는 학생 OAuth와 별개의 **로컬 자격증명** (username/password)으로 로그인합니다. 학생 흐름과 토큰이 분리되어 있어 동시에 두 세션을 가질 수 있습니다.

## 0. 로그인

1. `https://lib.your-domain.kr/admin/login` 접속.
2. 운영자가 발급한 **username** + **password** 입력 → **`로그인`**.
3. 성공 시 `/admin` 대시보드로 자동 이동.

> 관리자 계정 발급은 운영팀이 DB에 직접 시드하는 단계입니다 (`backend/prisma/seed.ts` 참고). 셀프 서비스 가입은 의도적으로 차단되어 있습니다.

세션 토큰은 7일 유효. 만료 시 재로그인.

## 1. 대시보드 (`/admin`)

진입 카드:
- **도서 관리** → `/admin/catalog`
- **대출 관리** → `/admin/loans`
- **도서 추천 검토** → `/admin/suggestions`
- **수집 기간** → `/admin/collection-periods`

좌측 사이드바 (햄버거 메뉴)에서 같은 항목으로 이동 + **로그아웃** 버튼.

## 2. 도서 관리 (`/admin/catalog`)

### 2.1 목록 / 검색

- 보유 도서 전체 목록 (페이지네이션 — 페이지당 200건).
- 각 행: 제목 / 저자 / ISBN / 카테고리 / 보유 수량 / 대출 가능 수량.

### 2.2 도서 등록

1. 우측 상단 **`+ 도서 추가`** → 폼 다이얼로그.
2. 입력:
   - **제목** (필수)
   - **저자** (필수)
   - **카테고리** (필수)
   - **총 수량** (필수, 1 이상)
   - **대출 가능 수량** (필수, 0 이상, 총 수량 이하)
   - **ISBN** (선택, 10자리 또는 13자리 숫자, 중복 불가)
   - **발행연도** (선택, 1000 ~ 현재년도+1)
   - **표지 이미지 URL** (선택)
   - **설명** (선택)
3. **`저장`**.

> ISBN이 이미 있으면 400 에러 + 메시지 표시. ISBN을 중복 검사하지 않으려면 빈 칸으로 두세요.

### 2.3 도서 수정

1. 행의 **`수정`** 아이콘 → 사전 채워진 폼.
2. 변경 후 **`저장`**.

### 2.4 도서 삭제

1. 행의 **`삭제`** 아이콘 → 확인 다이얼로그.
2. **활성 대출 / 대기 신청이 있으면** 409 에러 + 차단:
   - "현재 N건 대출 중 / M건 신청 대기" 메시지 표시.
   - 강제 삭제하려면 모든 대출/신청을 먼저 정리해야 함.

## 3. 대출 관리 (`/admin/loans`)

### 3.1 대출 신청 검토

- **`대기 중 (pending)`** 신청 목록.
- 각 신청에 대해:
  - **`승인`** → 학생이 책을 받아갈 수 있음. 도서의 `availableQuantity`가 자동 차감.
  - **`반려`** → 학생에게 표시 (선택적 사유 메모).

> 승인 시 책의 가용 수량을 0 미만으로 만드는 신청은 자동으로 차단됩니다 (백엔드 검증).

### 3.2 활성 대출 추적

- 현재 대출 중인 도서 + 학생 + 대출일 + 반납 예정일 목록.
- **`반납 처리`** 버튼:
  - 가용 수량을 1 증가.
  - 해당 도서에 대기 중인 첫 예약자가 있으면 자동 **알림 상태로 전환** (24시간 시한).
  - 다음 학생이 대출 처리하면 알림 → fulfilled로.

## 4. 도서 추천 검토 (`/admin/suggestions`)

### 4.1 그룹 카드

같은 책 (제목 + 저자) 추천이 여러 학생에게서 들어오면 한 카드로 그룹화:

- 상단: 책 정보 + **`추천 N명`** 배지
- 상태 칩: `제출됨 N` / `검토중 M` / `승인 K` / `반려 L`
- 하단: 개별 학생 추천 행 (제출일 / 사유 / 관리자 메모)

### 4.2 개별 추천 액션

상태가 `제출됨` 또는 `검토중`인 행에서:

- ✅ **`승인`** → 다이얼로그 → 관리자 메모 (선택) → 저장.
- ❌ **`반려`** → 다이얼로그 → 관리자 메모 → 저장.
- ⏳ **`검토중`** → 일단 보류 (학생에게 "검토 중" 표시).

### 4.3 승인 추천 → 카탈로그 직행

상태가 **`승인`**으로 바뀐 행에는 **`카탈로그에 등록`** 액션이 추가로 노출:

1. 액션 탭 → 도서 등록 다이얼로그가 열림 (제목/저자 자동 입력됨).
2. 카테고리·수량·ISBN 등 나머지 필드 입력.
3. **`카탈로그에 등록`** → 도서 생성 + 스낵바 확인.

> 추천 → 카탈로그 등록은 별개 트랜잭션입니다. 추천 상태는 `approved`로 유지되고, 책은 새로운 row로 들어갑니다 (추천과 자동 연결되지는 않음).

## 5. 수집 기간 관리 (`/admin/collection-periods`)

### 5.1 새 기간 생성

1. 폼 입력:
   - **이름** (필수, 100자 이내)
   - **시작일** (캘린더 픽커)
   - **종료일** (시작일 이후)
   - **상태**:
     - `예정 (upcoming)` — 아직 추천 받지 않음
     - `활성 (active)` — 학생이 추천 가능
     - `종료 (closed)` — 추천 차단
2. **`기간 생성`**.

> **중요**: 새 기간을 `active`로 만들면 **기존에 active였던 기간이 자동으로 closed로 전환됩니다**. 한 시점에 active 기간은 항상 1개 이하.

### 5.2 학생 화면에서의 영향

학생 앱은 항상 `active` 상태인 첫 번째 기간을 표시합니다. `closed`로 전환된 기간의 추천 폼은 자동으로 비활성화됩니다.

## 6. 운영 팁

- **추천 검토 우선순위**: `requesterCount`가 높은 카드부터. 수요가 명확함.
- **반납 알림 누락 방지**: `notified` 상태 예약은 24시간 시한 — 가능한 한 빨리 학생이 대출하도록 안내.
- **기간 닫기 전 정리**: 종료 직전 `submitted` 상태 추천을 일괄 처리 (`반려` 또는 `검토중`).
- **카탈로그 데이터 일관성**: ISBN을 가능한 한 입력 → 중복 등록 자동 차단됨.

## 7. 트러블슈팅

| 증상 | 원인 / 해결 |
|--|--|
| 로그인 후 401 | 세션 만료. 다시 로그인. |
| 도서 삭제가 409로 거절됨 | 활성 대출/신청 존재. 먼저 반납/취소 처리. |
| 새 기간을 active로 못 만듦 | 기존 active 기간이 자동 closed 처리됩니다 — 정상 동작. |
| 추천이 보이지 않음 | 활성 수집 기간이 없거나, 기간 ID 필터 누락. 화면 새로고침. |
| 카탈로그 직행 시 ISBN 오류 | ISBN이 이미 등록됨. 빈 칸으로 두거나, 기존 도서를 수정. |
